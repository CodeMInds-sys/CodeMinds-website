Section 1

What is I²C?

I²C (Inter-Integrated Circuit) is a synchronous, address-based serial communication protocol that uses only two wires to connect multiple devices to a controller.

SDA
Serial Data
Carries the actual data bits between controller and targets. Bidirectional — both sides use the same wire, one at a time.
SCL
Serial Clock
Provides the timing pulses. The controller always drives SCL. It tells the receiver exactly when to read SDA — it does not carry data itself.
Controller
Master
Initiates all transactions, generates the clock, and selects which device to talk to using an address. Typically your microcontroller (ESP32, Arduino…).
Target
Slave
Responds when addressed by the controller. Can be an OLED display, sensor, EEPROM, etc. Each has a unique address.

Bus Topology

VCC | | ┌──────┴──────────────────────────────────────┐ │ ESP32 Controller │ └──────┬──────────────────────────────────────┘ │ SDA ──────────┬────────────┬──────────────── OLED 0x3C │ SCL ──────────┼────────────┼──────────────── MPU6050 0x68 │ │ EEPROM Sensor 0x50 0x76
Key insight: All devices share the same SDA and SCL wires. The controller selects a specific device by sending its unique 7-bit address at the beginning of every transaction. All other devices ignore the transaction silently.
Section 2

Full Duplex vs Half Duplex

Understanding data direction is critical. SPI can send and receive simultaneously; I²C cannot — it uses the same wire for both directions, one at a time.

MASTER SLAVE │ │ │ ──────── MOSI ──────────────► │ ← Master sends data to Slave │ ◄──────── MISO ────────────── │ ← Slave sends data to Master │ │ (simultaneously!) │ ──────── SCLK ──────────────► │ ← Clock from Master │ ──────── CS ──────────────► │ ← Chip select RESULT: Data flows in BOTH directions simultaneously → Full Duplex Requires 4 wires minimum (MOSI, MISO, SCLK, CS)
CONTROLLER TARGET │ │ │ ──────── SDA ──────────────► │ ← Controller writes data │ ◄──────── SDA ────────────── │ ← Target responds (ACK/read) │ │ (but NOT at the same time!) │ ──────── SCL ──────────────► │ ← Clock always from Controller RESULT: SDA is shared → only ONE direction active at a time → Half Duplex Requires only 2 wires (SDA, SCL) + pull-up resistors
Why Half Duplex?

I²C uses open-drain bus lines. When the line is released, a pull-up resistor pulls it HIGH. Multiple devices share the wire using this mechanism — they can pull LOW but never actively drive HIGH. This means only one device can drive SDA at a time, making simultaneous bidirectional transmission impossible.

Trade-offs
  • ✓ Only 2 wires (SDA + SCL)
  • ✓ Up to 127 devices on one bus
  • ✓ Simple routing and PCB layout
  • ✗ Slower than SPI in most cases
  • ✗ No simultaneous bidirectional flow
  • ✗ Protocol overhead per transaction

Why does SCL exist?

SCL — Clock Signal

SCL is the synchronization signal. It tells the receiver exactly when to read the SDA line. Without SCL, the receiver would not know when a stable bit is ready. SCL does NOT carry data.

SCL HIGH = sample SDA now
SCL LOW = SDA may change (prepare next bit)
SDA — Data Signal

SDA carries the actual bits. It must remain stable while SCL is HIGH so the receiver can reliably sample it. SDA changes are only permitted while SCL is LOW (except for START and STOP conditions).

SDA stable + SCL HIGH = valid bit
SDA changes + SCL LOW = preparing bit

Section 5

START & STOP Conditions

START and STOP are special bus conditions, not data bits. They are defined by changes on SDA while SCL is HIGH — which is normally forbidden during data transfer.

START Condition

SDA transitions from HIGH → LOW while SCL is HIGH.

This signals to all devices on the bus that a transaction is beginning. All targets begin listening for their address.

STOP Condition

SDA transitions from LOW → HIGH while SCL is HIGH.

This signals the end of the transaction. The bus returns to idle (both lines HIGH). Any device may now initiate a new transaction.

The 7-bit address occupies the upper 7 bits. The 8th bit (LSB) is the R/W bit: 0 = Write, 1 = Read. So address 0x3C (binary: 0111100) transmitted as a write byte becomes 0x78 on the wire (01111000). In your code, you only specify the 7-bit address (0x3C); the library handles the R/W bit automatically.

Section 7 — Interactive

ACK & NACK

After every byte (8 bits) is transmitted, the receiver must acknowledge receipt. This uses a 9th clock pulse on SCL. The ACK/NACK phase confirms the communication is working.

9th Clock SCL HIGH
Result Waiting…
Meaning Click "Send ACK" or "Send NACK" above.
ACK (Acknowledge)
SDA = LOW

The receiver pulls SDA LOW during the 9th clock pulse. This signals: "I received the byte successfully, send more."

When sent: Target to controller (after address byte), target to controller (after each data byte in read), controller to target (after each data byte in write).

NACK (Not Acknowledge)
SDA = HIGH

SDA remains HIGH during the 9th clock pulse. This signals: "Not ready", "Error", "No such device", or "Last byte in read."

When sent: Address doesn't match any device, device busy, controller sends NACK after last byte it wants to read.

Section 9

Pull-up Resistors

I²C uses open-drain bus lines. Devices can only pull the line LOW — they cannot actively drive it HIGH. Pull-up resistors complete the circuit by pulling idle lines HIGH.

VCC (3.3V or 5V) │ │ [4.7kΩ] [4.7kΩ] ← Pull-up resistors │ │ SDA ─┘ └─ SCL │ I²C │ ├──── Bus ──┤ │ │ ┌────┴────┐ ┌──┴──────┐ ┌────────────┐ │ ESP32 │ │ OLED │ │ MPU-6050 │ │ (ctrl) │ │ 0x3C │ │ 0x68 │ └─────────┘ └─────────┘ └────────────┘ Open-drain outputs: can pull LOW, but only resistor can pull HIGH
Why Open-Drain?

Open-drain allows multiple devices to share the bus safely. If two devices tried to simultaneously drive the line (one HIGH, one LOW), they would short-circuit. With open-drain, devices only pull LOW — the resistor provides HIGH when no device is pulling.

Resistor Values

Typical values: 2.2kΩ – 10kΩ. Lower values provide faster rise times (better for high-speed I²C) but draw more current. Higher values save power but limit speed. Most designs use 4.7kΩ as a safe default.

ESP32 Internal Pull-ups

The Wire library on ESP32 can enable internal pull-up resistors, which are typically ~45kΩ. This may work for short cables and low speed, but external 4.7kΩ resistors are strongly recommended for reliable communication.

Section 10 — Interactive

Clock Stretching

Sometimes a target device needs more time to prepare data. Rather than losing synchronization, I²C allows the target to hold SCL LOW until it is ready. This is clock stretching.

⏱️
Controller drives SCL HIGH
The controller finishes sending a byte and raises SCL to start the ACK clock pulse.
🛑
Target holds SCL LOW
The target is not ready (e.g., still processing the command). It uses its open-drain pin to hold the SCL line LOW, even though the controller tried to raise it.
⏳
Controller detects stretched clock and waits
The controller reads back SCL and finds it still LOW. It enters a wait state, halting the clock. A well-designed controller handles this gracefully; some simpler controllers may time out.
✅
Target releases SCL
When the target is ready, it releases its hold on SCL. The pull-up resistor raises SCL HIGH. The controller sees SCL go HIGH and resumes the transaction normally.
Section 11 — Practical

OLED Practical Lab

Connect an SSD1306 I²C OLED display to an ESP32. Below is the wiring, library explanation, and complete code.

Wiring Diagram
ESP32 OLED SSD1306 ──────────────────────────────── 3.3V ─────────────── VCC GND ─────────────── GND GPIO21 ────────────── SDA GPIO22 ────────────── SCL ──────────────────────────────── + 4.7kΩ pull-ups on SDA & SCL to 3.3V (or use module's)
Note: GPIO21/22 are ESP32's default I²C pins. Some boards (ESP32-S2, S3, C3) use different defaults. Check your board's pinout.
VCC

Powers the OLED. SSD1306 operates at 3.3V (or 5V on some modules via onboard regulator). Match to your ESP32's logic level — always use 3.3V for pure 3.3V ESP32 boards.

GND

Common ground. Always connect GND between controller and all I²C devices. Without a shared GND, voltage levels are meaningless.

OLED Address

Set by the SA0 pin on the SSD1306. Use an I²C scanner to confirm your module's actual address before writing code.

Required Libraries

Wire.h
Built-in

Arduino's I²C library. Handles all low-level I²C protocol: START/STOP conditions, addressing, byte transmission, and ACK handling. Wire.begin(SDA, SCL) initializes the bus.

Adafruit_GFX.h
Install via Library Manager

Graphics abstraction layer. Provides text drawing, shapes, bitmaps, and pixel operations. Platform-independent — works with any display driver.

Adafruit_SSD1306.h
Install via Library Manager

Hardware driver for the SSD1306 OLED controller. Translates GFX drawing commands into I²C messages that the display's controller chip understands.

Line-by-Line Explanation

  

    

      
Wire.begin(21, 22)

      
Initializes the I²C peripheral with SDA=GPIO21 and SCL=GPIO22. Configures the pins, enables internal pull-ups, and sets the clock speed (default 100kHz).

    

    

      
Wire.beginTransmission(addr)

      
Queues a START condition + address byte to be sent. The address is the 7-bit device address. This does not yet transmit anything.

    

    

      
Wire.endTransmission()

      
Actually sends the queued data (START + address + data if any + STOP). Returns 0 if the address was acknowledged (device found), or an error code if no device responded.

Both are popular synchronous serial protocols. Choose based on your wiring constraints, speed requirements, and number of devices.
